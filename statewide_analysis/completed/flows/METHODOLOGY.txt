Rachel-only Senate Sankey

Every numerical node, link and path count is recomputed from rank1-rank5 of
inputs/Alaska_20261103_US_Senate_11_11.csv. The input must exist; no prior archive,
cleaned CVR, old aggregate patterns, old results, or fallback sources are loaded.
The input SHA-256 and row count are saved in senate_sankey.json.

The CSV's generic overvote token stops later preferences. A pair of consecutive
internal skipped tokens stops later preferences. One skip is crossed. Repeated
candidate names are collapsed in the interpreted prefix. A write-in occupies its
original position, including between blanks. Rank1 ancillary ambiguity/overvote
candidate-name metadata is not used to override Rachel's supplied rank tokens.
Unmodified token-level data remain in the source CSV and aggregated pattern CSV.

Four predeclared replay stages retain the original preference prefix and remove:
1. no candidate; 2. generic write-in; 3. Daniel J. Sullivan Jr.; 4. Gerald Heikes.
Each ballot goes to its highest remaining candidate, or Inactive. All rows remain
at every stage, including initially inactive ballots. Each node's incoming/outgoing
flow and each full stage total are checked for exact mass conservation.

The frozen FairVote HTML is parsed only after counts have been derived. Its 18
numeric cells are an external published benchmark; discrepancies would be retained
and never used to adjust Rachel-derived counts. FairVote's inactive series excludes
initially inactive ballots; only this benchmark comparison subtracts that baseline.
The diagram itself includes the full Rachel CSV cohort throughout.

build_flows.py generates all assets; Python standard library suffices for SVG/HTML
and tables. Pillow optionally generates PNG. Generic candidate keys in outputs are
locally defined readable identifiers, not claimed to be Rachel's numeric IDs.
This is a preliminary four-stage replay, not certified official election results.
